  요청 방식)을 CT 작업에 맞게 옮겨 저장소를 만들었다.

  AGENTS.md에 적었다.
- 첫 서버 PC 요청은 환경 점검(`todo.md` 1절)이다.

## 2026-10-29 다음 기능을 목록대로 입력·출력 지정으로 바꿈

- 사용자가 함수마다 하는 일은 테스트 생성, 자동 케이스 정리, 목록 보며 변수마다 입력·출력
  지정, 커버리지 채우기 순이다. 이 중 입력·출력 지정이 가장 손이 많이 간다고 해서 로드맵 맨
  앞에 두고, CLI.ini 래퍼는 뒤로 미뤘다.
- 목록은 Codebeamer에서 내보낸다. 형식은 툴킷이 정하고 사용자가 맞춘다.
- 방식은 CT가 만든 테스트를 내보내 고치고 다시 가져오는 B로 정했다. 목록만으로 테스트 데이터를
  만들어 넣는 A와 범위 칸 활용은 나중이다. 자동 케이스 정리는 옵션으로 함께 한다.
- 내보낸 파일의 형식이 매뉴얼에 없어 지어낸 함수(`examples/ct_sample`)로 지정 전후를 비교하는
  견본을 `todo.md` 2절로 요청했다.

## 2026-10-29 CT 견본(todo.md 2절) 결과

- 지어낸 함수 `dmy_calc`로 지정 전후를 [테스트 내보내기]해 `fc`로 비교했다. 내보낸 폴더에는
  `testInfo.export`와 `UNITTESTS\dmy_calc_test0.csv`만 있었고, 지정을 바꾸자 CSV만 바뀌었다.
- 지정은 CSV 머리글 줄의 `<input>`, `<expect>` 구역에 어떤 기호가 들어 있느냐로 적힌다.
  `<output>`, `<toutput>`은 `<expect>`와 같은 기호다. 구조체는 멤버, 배열은 원소, 포인터
  파라미터는 `<이름>_mem[i]`, 리턴은 `returnVar`로 나온다. 그래서 B 방식은 성립하고 타입으로
  거르지 않기로 했다.
- 사용자가 목록에 없는 `dmy_spare`를 입력에서 뺐다. 설계에서 "목록에 없는 변수는 그대로 둔다"를
  "지정 해제"로 바꾸고, 화면에 해제 수를 찍기로 했다.
- `fc`는 127자가 넘는 줄을 나눠 찍어 줄 번호가 실제보다 많게 보인다. CSV 첫 줄, 인코딩,
  `testInfo.export` 원문과 다시 가져오기 동작은 todo.md 4절로 요청했다.
- 사용자 요청으로 todo.md 3절에 Codebeamer 목록을 만드는 형식(머리글, 변수 이름 적는 법, 예시 표)을
  적었다.
