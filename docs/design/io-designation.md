# 목록대로 입력·출력 지정하기

상태: 사용자 승인(2026-10-29). CT 파일 형식에 기대는 부분은 [todo.md](../../todo.md) 견본
결과로 채운다. 구현 계획은 [io-designation-plan.md](io-designation-plan.md). 2026-11-02 견본 결과로
가져오기 단계를 "CSV로 테스트 생성하기"로 바꿨다(사용자 승인 2026-11-02, 아래 "사용 흐름").

## 왜

사용자는 함수마다 아래 순서로 CT 단위 테스트를 만든다.

1. 함수를 골라 테스트를 만든다.
2. 자동 생성된 테스트 케이스를 지우고 하나 새로 만든다.
3. 따로 있는 목록을 보며 변수마다 입력인지 출력인지 하나씩 지정한다.
4. 값을 넣고 돌려 커버리지를 채운다.

가장 귀찮은 것은 3단계다. 함수 수 × 변수 수만큼 같은 클릭을 반복하는데, 무엇을 고를지는 이미
목록에 다 적혀 있다. 이 기능은 그 목록을 읽어 3단계를 한 번에 끝낸다. 옵션을 주면 2단계도 함께
한다(사용자 답).

목록은 사용자가 Codebeamer에서 내보낸다. 형식은 툴킷이 정하고 사용자가 거기에 맞춘다.
목록에는 변수마다 입력·출력 구분, 타입, 범위 설명이 있다.

## 방식

CT가 만든 테스트를 내보내 툴킷이 테스트 데이터 CSV의 머리글을 고치고, 사용자가 그 CSV로 CT에서
테스트를 다시 만든다(B 방식). [테스트 가져오기]는 지정을 CSV가 아니라 `.utest`(바이너리)에서 읽고,
[테스트 데이터로 테스트 생성하기]는 CSV 머리글대로 지정한다(아래 견본 결과 8·9절).

- CT가 테스트를 만들었으니 변수 이름과 타입은 CT가 아는 그대로다. 툴킷은 목록과 맞춰 보고
  지정만 바꾼다.
- 매뉴얼상 원시 타입이 아닌 변수도 "CT에서 내보낸 테스트 데이터를 수정하여 다시 가져오는 경우"에는
  들어간다(2025.12 테스트 공유).
- CT GUI 조작이 내보내기·가져오기 두 번 늘어난다. 대신 함수 여러 개를 한 번에 처리한다.

목록만으로 테스트 데이터 파일을 처음부터 만들어 "테스트 데이터로 테스트 생성하기"로 넣는
방식(A)은 나중에 만든다. A는 내보내기가 필요 없지만 원시 타입만 들어가고, 목록의 변수 이름이
CT 안의 이름과 맞는지 미리 알 수 없다.

## 목표

- XLSX 목록대로 CT 테스트 데이터 CSV의 입력·출력 지정(머리글)을 바꾼 사본을 만든다. 함수 여러
  개를 한 번에 한다.
- `--reset-cases` 옵션을 주면 지정을 바꾼 테스트의 케이스를 모두 지우고 값 없는 케이스 하나만
  둔다(2단계). 옵션이 없으면 케이스를 건드리지 않는다.
- 툴킷이 처리하지 못한 줄은 건너뛰고 이유별 개수를 찍는다. 사용자는 그것만 손으로 마저 한다.
- 목록의 범위 칸은 읽어 두기만 한다. 다음 단계에서 쓴다.

## 하지 않는 것

- 범위 활용(경계값 입력, 변수 파티션). 다음 단계다.
- A 방식. 나중에 만든다.
- 값과 기대값 채우기, 커버리지 채우기(4단계).
- 1단계(테스트 생성)와 CT 가져오기의 자동화. CLI.ini의 `[CreateTest]`, `[ImportTest]`로 될 수
  있지만 [로드맵](roadmap.md)의 CLI 래퍼에서 다룬다.
- CT GUI 자동 조작.

## 실패로 치는 것

기능이 돌더라도 아래 중 하나면 실패다.

- 화면, 로그, 커밋에 고객의 함수·변수·파일 이름이나 경로가 찍힌다.
- 조용히 틀린다. 목록의 줄을 처리하지 못했는데 개수에 잡히지 않거나, 목록에 없는 것을 말없이
  바꾼다.
- 사용자가 해 둔 수작업(다른 테스트, 이미 넣은 값)이 사라진다. `--reset-cases`를 준 테스트의
  케이스만 예외다. 사용자가 지우라고 한 것이다.

## 제약

- 서버 PC: CT 2025 (V3) 빌드 20251127, CT CLI는 `csc.exe`, Python 3.14.7, openpyxl 3.1.5.
  코드는 Python 3.8 이상에서 돌게 쓴다([AGENTS.md](../../AGENTS.md)).
- 툴킷은 서버 PC에서 `ct.bat <명령>`으로 돈다. 에이전트는 서버 PC에 닿지 않아, 실행 확인은
  todo.md 요청과 화면 캡처 한 장으로 한다.
- 내보낸 테스트 파일의 형식은 매뉴얼에 없다. 견본으로 정한다(아래 "견본으로 정할 것").
- CT는 같은 함수의 테스트를 다시 넣으면 덮어쓰지 않고 새 이름(`<함수>_test<N>`)으로 만든다(견본
  4·8·9절). 그래서 사용자가 원래 테스트를 먼저 지운다.

## 사용 흐름

1. Codebeamer에서 목록을 XLSX로 내보낸다(형식은 아래).
2. CT에서 대상 함수들의 테스트를 만든다. 여러 함수를 한 번에 만들어도 된다. 자동 생성된
   케이스는 지우지 않고 둔다.
3. [내보내기] > [테스트] > [테스트 내보내기]로 새 빈 폴더에 내보낸다. 유닛 테스트는 테스트와
   테스트 데이터 둘 다. CT에 같은 함수의 테스트가 여럿 있거나 옛 CSV가 남은 폴더에 내보내면 그 함수의
   테스트가 둘 이상 읽혀 "함수 여럿"이 된다. [환경 설정] > [테스트] > [데이터 내보내기]는 [가로]여야 한다(아래 "견본 결과" 13절).
4. `ct.bat io-apply --list <목록.xlsx> --export <내보낸 폴더> --reset-cases`를 돌린다. 툴킷은
   내보낸 폴더를 읽기만 하고, 머리글을 고치고 케이스를 정리한 CSV를 `result\io\<yyyyMMdd_HHmmss>\`에
   원래 상대 경로 그대로 쓴다. 값까지 넣은 테스트에 다시 돌릴 때는 `--reset-cases`를 빼야 값이 남는다.
   서버 PC는 명령을 창에 칠 수 없어 저장소 루트의 `io-apply.bat`을 더블클릭한다. 목록 파일과 내보낸
   폴더를 창에 끌어다 놓고, 케이스 정리를 `y`/`n`으로 고르면 같은 명령이 돈다(`tools/io_run.py`).
5. CT에서 화면의 "바꾼 것" 테스트(사본에 CSV가 있는 테스트)의 원래 것을 지운다. 지울 테스트는 사본
   폴더의 CSV 이름과 같은 것이다. 지우지 않으면 같은 함수의 테스트가 둘이 된다. 잘못 지웠으면 내보낸
   폴더를 [테스트 가져오기]로 넣어 되살린다.
6. [가져오기] > [테스트] > [테스트 데이터로 테스트 생성하기]에서 [추가…]로 사본의 CSV를 모두 고르고
   [완료].
7. 화면에 찍힌 건너뜀 개수만큼 `skipped.txt`를 보고 손으로 지정한 뒤 값 넣기로 넘어간다.

명령 이름 `io-apply`와 옵션 이름은 구현하면서 바꿔도 된다.

## 목록 형식

XLSX 첫 시트, 첫 줄이 머리글이다. 칸은 머리글 이름으로 찾으므로 순서와 다른 칸이 더 있는 것은
상관없다.

| 머리글 | 값 | 비어도 되나 |
| --- | --- | --- |
| `함수` | 함수 이름 | 아니오 |
| `변수` | 전역 변수·파라미터 이름. 리턴은 `return` | 아니오 |
| `구분` | `입력`, `출력`, `입출력` 중 하나 | 아니오 |
| `파일` | 함수가 있는 소스 파일 이름. 적혀 있으면 내보낸 테스트의 소스 파일과 맞춰 보고, 다르면 내보내지 않은 함수로 친다 | 예 |
| `타입` | 목록에 적힌 타입 이름 | 예 |
| `범위` | 범위 설명. 읽기만 한다 | 예 |

- Codebeamer 내보내기를 이 형식에 맞추는 것은 사용자가 한다(사용자 답). 머리글 별칭이나 칸
  안의 값 나누기는 만들지 않는다.
- 같은 함수의 줄이 붙어 있지 않아도 된다.
- 목록은 컴포넌트 전체여도 되고 이번에 내보낸 함수만이어도 된다(아래 "맞춰 보기").
- 앞뒤 공백은 지운다. 이름은 대소문자를 구분한다(C 이름이므로).
- 구조체 멤버를 따로 지정하는 줄(`a.b`)은 첫 버전에서 받지 않는다. 변수 단위로만 지정한다.
- 구현할 때 지어낸 이름의 예제 목록을 `examples/`에 `*.example.xlsx`로 둔다.

## 맞춰 보기

목록의 줄마다 내보낸 폴더에서 그 함수의 테스트를 찾고, 그 테스트 안에서 변수를 찾아 지정을
바꾼다. 처리하지 못한 줄은 아래 이유 중 하나로 센다. 사용자가 손으로 마저 할 것은 이 "건너뜀"뿐이다.

| 이유 | 언제 |
| --- | --- |
| 목록 오류 | 필수 칸이 비었거나 `구분` 값이 정해진 것 밖이다 |
| 함수 여럿 | 같은 이름의 테스트가 둘 이상인데 `파일` 칸이 비었거나 `파일`로도 하나로 좁혀지지 않는다 |
| 변수 없음 | 테스트에 그 이름의 변수가 없다 |
| 목록 충돌 | 같은 함수·변수 줄이 둘 이상인데 `구분`이 다르다 |
| 값 있음 | 지정이 바뀌는 변수에 테스트 케이스 값이 이미 들어 있다(값을 잃지 않게 건너뛴다) |
| 타입 제외 | 툴킷이 그 종류의 지정을 쓸 줄 모른다(아래) |

같은 함수·변수 줄이 `구분`까지 같으면 하나로 친다.

목록과 내보낸 폴더가 함수 단위로 어긋나는 것은 건너뜀과 따로 센다. 목록이 컴포넌트 전체여도
건너뜀이 부풀지 않게 하려는 것이다.

- **내보내지 않은 함수:** 목록에는 있는데 내보낸 폴더에 테스트가 없다. 이번에 다루지 않는
  함수로 보고 개수만 찍는다.
- **목록에 없는 테스트:** 내보낸 폴더에는 있는데 목록에 그 함수 줄이 없다. 함수 이름 오타를
  잡는 쪽이 이것이다. 개수를 찍고 함수 이름은 `skipped.txt`에 쓴다. 사본에는 넣지 않는다.

**값이 든 테스트.** 흐름상 지정은 값 넣기(4단계)보다 먼저라 보통 값이 없다. 목록이 바뀌어 값까지
넣은 테스트에 다시 돌려도 툴킷은 값을 건드리지 않고, 지정이 바뀌는 변수에 값이 있으면 그 줄을
"값 있음"으로 건너뛴다. 값이 있다는 것은 케이스 줄에서 그 변수의 기호 칸이 하나라도 비어 있지
않다는 뜻이다(아래 "견본 결과").

**타입.** 견본에서 구조체(`dmy_limit`), 배열(`dmy_hist`), 포인터 파라미터(`dmy_ptr`)도 원시 타입과
같은 방식으로 지정이 적혔다(아래 "견본 결과"). 그래서 타입으로 거르지 않는다. 목록의 `타입` 칸은
typedef 이름처럼 표기가 달라 맞추기 어려우므로 비교하지 않는다. "타입 제외"는 내보낸 파일에서
아래 네 꼴로 읽을 수 없는 기호를 만났을 때만 센다.

**목록에 없는 변수.** 지정을 해제한다. 그 변수의 기호를 입력·기대값 구역에서 모두 뺀다. 2절
견본에서 사용자가 목록에 없는 `dmy_spare`를 입력에서 뺐기 때문이다(처음 설계는 그대로 두기였고,
2절 답을 따르기로 했었다). 말없이 바꾸지 않도록 화면에 해제한 변수 수를 찍고 이름은
`skipped.txt`에 "목록에 없어 해제"로 쓴다. 목록에 함수 줄이 하나도 없는 테스트는 사본에 넣지
않으므로 해제하지 않는다. 단, 케이스 값이 든 변수는 `--reset-cases`를 주지 않는 한 해제하지
않는다(값을 잃지 않게). 그런 변수는 화면에 "값 있어 둠" 개수로 세고 이름은 `skipped.txt`에
"목록에 없지만 값 있음"으로 쓴다. 목록의 어느 줄이든 이름을 붙인 변수(와 포인터 파라미터의 `_mem`
꼴)는 그 줄을 건너뛰었어도, 함수 여럿으로 버렸어도 해제하지 않는다.

**멤버마다 지정이 다른 변수.** 구조체·배열 변수의 기호들이 든 구역(`<input>`, `<expect>`)이 서로
다르면(예: 멤버 하나는 입력·기대값, 다른 멤버는 입력에만) 지금 지정을 하나로 말할 수 없다. 이런
변수의 방향은 `mixed`로 읽어 목록의 지정과 늘 다른 것으로 본다. 그래서 바뀌는 변수로 세고 모든
기호에 목록의 지정을 같게 쓴다. 값이 든 `mixed` 변수는 `--reset-cases`를 주지 않으면 "값 있음"으로
건너뛴다. 목록에 없는 `mixed` 변수는 다른 변수처럼 해제한다.

**테스트 케이스.** `--reset-cases`를 주면 지정을 바꾼 테스트마다 케이스를 모두 지우고 값 없는
케이스 하나를 둔다. 자동 생성된 케이스와 사람이 만든 케이스를 가려내지 않는다. 그래서 기본은
꺼져 있고, 이 옵션을 준 테스트에는 "값 있음" 건너뜀을 적용하지 않는다(값을 지우라고 했으므로).
케이스 이름과 값 없는 케이스의 형식은 견본에서 CT가 쓴 것을 따른다. 지정을 바꾸지 않은 테스트
(목록에 없는 테스트 등)는 사본에 넣지 않으므로 케이스도 정리하지 않는다.

## 사본

- 내보낸 폴더는 읽기만 한다. 사본은 매번 새 `result\io\<시각>\` 폴더에 쓴다.
- 사본에는 테스트 데이터 CSV만 넣는다. `.utest`와 `testInfo.export`는 넣지 않는다(CSV로 테스트를
  만들 때 쓰지 않는다). 파일 이름과 상대 경로는 원본 그대로 둔다(매뉴얼: 이름 형식이 틀리면 테스트가
  안 생긴다).
- 지정이 실제로 바뀌는 테스트만 넣는다. 목록대로 지정해도 지금과 같고 해제할 변수도 없는 테스트는
  넣지 않는다. 사용자가 그 테스트를 지우고 다시 만들 일이 없게 하려는 것이다.
- 머리글과 케이스 칸 말고는 바꾸지 않는다. 첫 두 줄, 인코딩, 줄 끝, 따옴표, 모르는 구역(`<input>`,
  `<expect>`, `<output>`, `<toutput>` 밖)은 그대로 둔다. 바꿀 것이 없는 CSV를 다시 쓰면 원본과 바이트까지
  같아야 한다(단위 테스트).
- 함수 이름은 CSV 둘째 줄의 테스트 이름(`<함수>_test<N>`)에서 얻는다. 그 꼴이 아니면 같은 이름
  `.utest` 안의 함수 시그니처 글자열에서 얻는다. 소스 파일 이름(`파일` 칸 맞추기용)도 `.utest` 안의
  소스 경로 글자열에서 얻는다(확장자의 대소문자는 가리지 않는다). `.utest`는 읽기만 하고 고치지 않는다.
- **이름 꼴이 아닌 테스트.** 테스트 이름이 `<함수>_test<N>` 꼴이 아니면(함수를 `.utest`에서 찾았거나 못
  찾은 것) 맞춰 보기에는 쓰지만 사본에는 넣지 않는다. CT의 [테스트 데이터로 테스트 생성하기]가 이름
  꼴이 틀린 CSV로는 테스트를 만들지 않아(매뉴얼 2025.12 테스트 공유), 사용자가 원래 테스트를 지운 뒤
  되살릴 수 없기 때문이다. 지정이 바뀔 테스트였는데 뺀 것만 화면의 "안 다룸" 줄에 개수로 세고, 함수
  이름은 `skipped.txt`에 쓴다. 뺀 테스트의 지정·해제는 화면과 `skipped.txt`에서도 세지 않는다.
- **읽는 CSV.** 내보낸 폴더에서 `UnitTests` 폴더(대소문자 무시)의 CSV만 읽는다. 통합 테스트 등 다른
  폴더의 CSV는 단위 테스트가 아니라 읽지도, 읽지 못한 CSV로 세지도 않는다. 거기 CSV가 하나도 없으면
  "CSV가 없음", 있는데 CT 테스트 데이터 꼴이 하나도 없으면 "CT 꼴이 아님"이라는 정해 둔 문구로 멈춘다.
  따옴표 안에 줄바꿈이 든 CSV(한 줄의 `"`가 홀수)는 줄 단위로 칸을 맞출 수 없어 읽지 못한 CSV다.

## 화면과 기록

화면은 한 화면 안에 개수만 찍는다.

```text
목록      함수 12, 줄 148, 목록 오류 2
테스트    내보낸 것 15, 바꾼 것 10, 케이스 정리 10, 목록에 없는 것 1
지정      변수 131(그중 바뀜 40), 목록에 없어 해제 7, 값 있어 둠 0
안 다룸   내보내지 않은 함수 2, 읽지 못한 CSV 0, 이름 꼴이 아닌 테스트 0
건너뜀    함수 여럿 0, 변수 없음 9, 목록 충돌 0, 값 있음 0, 타입 제외 4
사본      result\io\20261029_153000\ (CSV 10)
건너뛴 줄 result\io\20261029_153000\skipped.txt
다음: CT에서 바꾼 테스트의 원래 것을 지우고 [테스트 데이터로 테스트 생성하기]로 사본 CSV를 넣기
```

- "바꾼 것"은 사본에 CSV를 쓴 테스트 수다. "지정 변수"는 목록대로 맞춘 변수 수이고, 괄호 안은 그중
  지정이 실제로 바뀐 수다. "읽지 못한 CSV"는 내보낸 폴더의 `UnitTests` CSV 중 CT 테스트 데이터 꼴이
  아닌 것이다. "이름 꼴이 아닌 테스트"는 지정이 바뀔 테스트였지만 이름 때문에 사본에서 뺀 수다(위
  "사본"). 바꿀 테스트가 모두 그래서 사본이 0개이면 "다음" 줄 자리에 그렇다는 정해 둔 문구가 나온다.
- 이름은 `skipped.txt`에만 쓴다. 건너뛴 줄은 목록의 행 번호, 함수, 변수, 이유. 목록에 없는
  테스트는 함수 이름. 해제한 변수와 값 때문에 둔 변수는 함수·변수 이름과 이유, 이름 꼴이 아니라 뺀
  테스트는 함수 이름과 이유, 읽지 못한 CSV는 내보낸 폴더 기준 상대 경로. 이 파일은 서버 PC에서만 보고
  밖으로 보내지 않는다.
- 오류는 종류와 할 일만 찍는다. 예: 목록을 열 수 없음(XLSX인지, 엑셀에서 열려 있지 않은지
  확인), 내보낸 폴더에 테스트가 없음(테스트 내보내기에서 유닛 테스트를 체크했는지 확인).
  예외 메시지 원문은 화면에 찍지 않는다.
- 실행 로그(`command_scope`)에는 시작·끝, 목록 읽기·내보낸 폴더 읽기·사본 쓰기 앞뒤 체크포인트,
  건너뜀이 있으면 이유별 개수를, 읽지 못한 CSV·이름 꼴이 아니라 뺀 테스트·값 있어 둔 변수가 있으면 그
  개수를 WARN으로 남긴다.
  해제한 변수 수는 INFO다. 로그에도 이름은 넣지 않는다. WARN은 콘솔에도 찍히기 때문이다.
- 단위 테스트에 `secret`이 든 함수·변수·경로 이름을 넣고 화면과 로그에 없는지 본다.
